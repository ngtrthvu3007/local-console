# DynamoDB Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Thêm service DynamoDB vào Local Console: bảng, duyệt/sửa item, Import/Export JSON, TTL, Stream và trigger Lambda từ stream.

**Architecture:** Giống S3 và Lambda: trình duyệt gọi Floci bằng AWS SDK qua proxy `/aws`, mỗi thao tác là một hook TanStack Query, giao diện Cloudscape. Logic khó (đổi dạng JSON, dựng expression) tách thành hai module thuần `itemJson.ts`, `expressions.ts`. Phần tạo trigger stream dùng chung giữa Lambda và DynamoDB.

**Tech Stack:** React 19, Cloudscape, TanStack Query 5, zod + react-hook-form, `@aws-sdk/client-dynamodb`, `@aws-sdk/util-dynamodb`, Vite.

**Spec:** [docs/superpowers/specs/2026-11-09-dynamodb-design.md](../specs/2026-11-09-dynamodb-design.md). Mã mục (vd: "3.5") trong plan trỏ tới mục của spec.

### Task 3: `itemJson.ts` — đổi dạng item

**Files:**

- Create: `dynamodb/itemJson.ts`
- Modify: `dynamodb/constants.ts` (thêm `ITEM_FORMATS = { json: "json", dynamodb: "dynamodb" }`, `CELL_PREVIEW_MAX_LENGTH = 80`, `ATTRIBUTE_VALUE_TYPES = ["S","N","B","BOOL","NULL","M","L","SS","NS","BS"]`)

**Interfaces:**

- Consumes: `KeyAttribute` (Task 1); `prettyJson`, `jsonError` từ `@shared/json.ts`; `marshall`, `unmarshall` từ `@aws-sdk/util-dynamodb`.
- Produces (`type Item = Record<string, AttributeValue>`, `type ItemFormat = "json" | "dynamodb"`):
  - `needsDynamoJson(item: Item): string | undefined` — trả lý do (để hiện ghi chú) nếu item (kể cả lồng trong M, L) có Set (`SS`/`NS`/`BS`), Binary (`B`), hoặc số mà `String(Number(text)) !== text`. Ngược lại `undefined`.
  - `toEditorText(item: Item, format: ItemFormat): string` — `json`: `prettyJson(unmarshall(item))`; `dynamodb`: `prettyJson` với Binary đổi thành chuỗi base64.
  - `parseEditorText(text: string, format: ItemFormat): Item` — ném `Error` với message cho người dùng. `json`: `JSON.parse` với reviver dùng `context.source`: số mà `String(value) !== context.source` → lỗi "The number {source} can't be stored exactly in JSON. Turn on DynamoDB JSON." Rồi `marshall(value, { removeUndefinedValues: true })`. Gốc không phải object → "The item must be a JSON object." `dynamodb`: kiểm tra đệ quy mỗi giá trị là object đúng **một** khóa trong `ATTRIBUTE_VALUE_TYPES`, đúng kiểu dữ liệu bên trong (N là chuỗi số, BOOL là boolean…); B/BS từ base64 thành `Uint8Array`. Lỗi ghi rõ đường dẫn attribute, vd: `"meta.count": expected {"N": "<number>"}`.
  - `keyError(item: Item, keys: KeyAttribute[]): string | undefined` — thiếu key hoặc sai kiểu.
  - `keyChanged(original: Item, next: Item, keys: KeyAttribute[]): boolean`.
  - `pickKey(item: Item, keys: KeyAttribute[]): Item`.
  - `cellText(value: AttributeValue | undefined): string` — theo 3.4: S, N nguyên văn; BOOL `true`/`false`; NULL `null`; M, L, Set → JSON thu gọn (`unmarshall`, số giữ nguyên chuỗi), cắt ở `CELL_PREVIEW_MAX_LENGTH` + `…`; B → `Binary (12 B)` (dùng `formatBytes`); `undefined` → `NOT_AVAILABLE`.
  - `exportText(items: Item[]): string` — mảng DynamoDB JSON (Binary → base64), `prettyJson`.
  - `parseImportText(text: string, format: ItemFormat, keys: KeyAttribute[]): Item[]` — gốc phải là mảng; mỗi phần tử qua cùng logic `parseEditorText` + `keyError`; lỗi đầu tiên ném `Error("Item {index + 1}: {message}")`.

- [ ] **Step 1: Viết `itemJson.ts`.** Chuyển base64 ↔ `Uint8Array` bằng `atob`/`btoa` (hàm nội bộ, không export).

### Task 4: `expressions.ts` — dựng Scan/Query

**Files:**

- Create: `dynamodb/expressions.ts`
- Modify: `dynamodb/constants.ts` (thêm `SORT_KEY_OPERATORS`, `FILTER_OPERATORS` kèm nhãn hiển thị, `FILTER_VALUE_TYPES = { S: "String", N: "Number", BOOL: "Boolean" }`), `dynamodb/schemas.ts` (thêm `itemSearchSchema`)

**Interfaces:**

- Consumes: `KeyAttribute`, `IndexKeys` (Task 1), `Item` (Task 3).
- Produces:
  - `type SortKeyOperator = "=" | "<" | "<=" | ">" | ">=" | "begins_with" | "between"`.
  - `type FilterOperator = "=" | "<>" | "<" | "<=" | ">" | ">=" | "begins_with" | "contains" | "exists" | "not_exists" | "between"`.
  - `ItemSearch = { mode: "scan" | "query"; indexName?: string; partitionKeyValue: string; sortKey?: { operator: SortKeyOperator; value: string; secondValue: string }; filters: { attribute: string; operator: FilterOperator; type: keyof typeof FILTER_VALUE_TYPES; value: string; secondValue: string }[]; descending: boolean }`.
  - `buildSearchInput(table: string, search: ItemSearch, keys: IndexKeys): ScanCommandInput | QueryCommandInput` (chưa có `Limit`, `ExclusiveStartKey`; hook thêm vào).
  - `itemSearchSchema(keys)`: Query bắt buộc partition key; giá trị kiểu Number phải là số; `between` cần cả hai ô; `begins_with` ở sort key chỉ cho key kiểu S; filter cần tên attribute; BOOL chỉ nhận `true`/`false`; `exists`/`not_exists` không cần giá trị.

Thuật toán (không suy ra được từ chữ ký):

```text
Tên luôn qua placeholder: key → #key0 (partition), #key1 (sort); filter i → #filter{i}.
Giá trị: :key0, :key1, :key1end (between); :filter{i}, :filter{i}end.
Giá trị key đổi theo kiểu key: S → {S}, N → {N}, B → {B: base64 → bytes}.
Giá trị filter theo type: S → {S}, N → {N}, BOOL → {BOOL: value === "true"}.
Sort key: "=",… → "#key1 <op> :key1"; begins_with → "begins_with(#key1, :key1)";
          between → "#key1 BETWEEN :key1 AND :key1end".
Filter: exists → "attribute_exists(#filter{i})"; not_exists → "attribute_not_exists(…)";
        contains/begins_with → "fn(#filter{i}, :filter{i})"; between như trên; còn lại "#… <op> :…".
Các filter nối " AND ". Query: KeyConditionExpression = "#key0 = :key0" [+ " AND " + sort],
ScanIndexForward = !descending. IndexName nếu có. Bỏ ExpressionAttributeValues khi rỗng.
```
