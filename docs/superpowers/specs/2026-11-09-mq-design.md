# Amazon MQ (RabbitMQ) — Thiết kế

> Ngày: 2026-11-09 · Trạng thái: đã làm (2026-11-09) · Thuộc: [Local Console](2026-11-09-localconsole-design.md)

## 1. Mục tiêu

Làm màn hình Amazon MQ giống AWS Amazon MQ Console, **chỉ gồm phần core** của spec chính (mục 4). Dev local dùng để:

- Xem đang có broker nào, lấy endpoint AMQP cho BE.
- Xem queue và exchange, số message trong từng queue.
- Publish một message thử, xem trước message đang nằm trong queue (không lấy mất), purge queue.
- Tạo nhanh broker hoặc queue để thử một luồng.

Phần broker đi qua AWS API của Floci (trình duyệt gọi SDK qua proxy `/aws`, giống DynamoDB). Phần queue đi qua **API quản lý của RabbitMQ**, qua backend. API này cần đăng nhập và chặn gọi từ trình duyệt (CORS), xem spec chính mục 2.

Floci chạy **RabbitMQ thật**, mỗi broker một container ([tài liệu Floci](https://floci.io/floci/services/amazonmq/)). Đã chạy thử trên Floci 2.4.0 trước khi làm (mục 6).

## 2. Phạm vi

### Làm trong đợt này (core theo spec chính)

| Nhóm     | Tính năng                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| Broker   | Liệt kê; tạo (tên, user/pass); xóa; reboot; hiện endpoint AMQP và link trang quản lý                          |
| Queue    | Liệt kê queue kèm số message; liệt kê exchange; tạo, xóa queue; publish message thử; xem trước message; purge |
| Theo dõi | Công tắc tự cập nhật danh sách queue mỗi 5 giây                                                               |

### Không làm trong đợt này

| Tính năng                                                                          | Lý do                                                                     |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Cột consumers/unacked, binding, publish kèm headers, cấu hình queue, copy AMQP URL | Đã đề xuất; user chốt chỉ làm core                                        |
| Chuyển message từ DLQ về queue gốc                                                 | Cần plugin shovel (tài liệu Floci không nhắc) hoặc tự lấy rồi publish lại |
| Tạo exchange; quản lý user, vhost, policy; biểu đồ message rate                    | BE tự khai báo topology; phần còn lại có ở trang quản lý của RabbitMQ     |
| ActiveMQ, Multi-AZ                                                                 | Floci chỉ hỗ trợ RabbitMQ `SINGLE_INSTANCE`                               |
| Vhost khác `/`                                                                     | Amazon MQ mặc định dùng `/`                                               |

## 3. Màn hình

Theo đúng quy tắc chung đã dùng cho DynamoDB và ElastiCache: chỉ dùng component và token của Cloudscape; mỗi vùng một nút chính; cột số căn phải (`Figure`); thiếu giá trị là "—"; trạng thái chỉ hiện khi khác bình thường; khung hẹp thì bảng thành hai tầng (`useIsCompact`); khối rỗng hoặc lỗi vẫn giữ khung.

### 3.1 Danh sách broker — `/mq/brokers`

```text
Brokers (1)                                            [↻] [Delete] [Create broker]
RabbitMQ brokers. Region: ap-southeast-1.
[🔍 Find brokers by name                     ]
 ☐ Name ▲              Engine           Created
 ☐ orders-mq           RabbitMQ 3.13    2026-11-09 10:11:01
 ☐ jobs-mq ◔ Creating  RabbitMQ 3.13    2026-11-09 10:12:40
```

- `ListBrokers`. Trạng thái chỉ hiện cạnh tên khi khác `RUNNING`; đang đổi trạng thái thì tự tải lại mỗi 2 giây.
- Bấm tên để mở trang chi tiết (đường dẫn dùng broker ID, tên hiện ở breadcrumb và header).
- Khung hẹp: tầng 1 là tên, tầng 2 là engine · ngày tạo.

### 3.2 Tạo broker — `/mq/brokers/create`

| Trường   | Ghi chú                                                                            |
| -------- | ---------------------------------------------------------------------------------- |
| Name     | 1–50 ký tự: chữ, số, `-`, `_`                                                      |
| Username | 2–100 ký tự: chữ, số, `-`, `.`, `_`, `~`. Không được là `guest`                    |
| Password | 12–250 ký tự, ít nhất 4 ký tự khác nhau, không có `,` `:` `=` (luật của Amazon MQ) |

- `CreateBroker`: RabbitMQ, `SINGLE_INSTANCE`, instance type và engine version cố định (Floci bỏ qua).
- Ghi chú dưới Password: "AWS doesn't return the password later. Keep it for your app's settings."
- Tạo xong thì mở trang chi tiết.

### 3.3 Chi tiết broker — `/mq/brokers/:broker`

```text
orders-mq                                       [Sign out] [Reboot] [Delete]
RabbitMQ 3.13
[Queues] [Exchanges] [Details]
```

- Tab lưu trên URL (`?tab=`). **Mặc định mở Queues.**
- Broker đang tạo/reboot: tab Queues và Exchanges hiện "Broker is …" kèm `StatusIndicator`, tự tải lại.
- Broker không tồn tại: "Broker … not found" kèm link về danh sách.

### 3.4 Đăng nhập broker

Tab Queues và Exchanges cần user/pass của broker, vì AWS API không trả lại password (spec chính, mục 4).

```text
┌ Sign in to orders-mq ───────────────────────────────────────┐
│ Use the user you set when you created the broker.          │
│ Username [admin        ]  Password [••••••••••]  [Sign in] │
└─────────────────────────────────────────────────────────────┘
```

- Lưu trong `sessionStorage` theo broker ID: còn khi tải lại trang, **mất khi đóng tab**. Đọc/ghi bọc `try/catch`; không lưu được thì vẫn dùng được trong lúc trang còn mở.
- Sai user/pass (401): xóa thông tin đã lưu, hiện lại form kèm lỗi "Wrong username or password".
- Đã đăng nhập thì header trang có thêm nút **Sign out** (cạnh Reboot, Delete) để đổi user.

### 3.5 Tab Queues

```text
Queues (3)            Auto refresh [○]  [↻] [Actions ▾] [Publish message] [Create queue]
[🔍 Find queues by name                ]
 ☐ Name ▲                   Type       Durable     Messages
 ☐ orders                   classic    Yes               12
 ☐ orders.dlq               classic    Yes                0
```

- Cột Messages là cột số. RabbitMQ cập nhật số này **chậm khoảng 5 giây**; mô tả dưới header ghi rõ.
- **Auto refresh** (`Toggle`): bật thì tải lại danh sách mỗi 5 giây. Mặc định tắt.
- Actions (chọn dòng): **Peek messages** (đúng 1 queue), **Purge** (đúng 1 queue), **Delete** (nhiều queue).
- Bấm tên queue cũng mở Peek messages.

| Thao tác        | Modal                                                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create queue    | Name; Durable (mặc định bật). Tên đã có thì báo "A queue with this name already exists"                                                                                                            |
| Publish message | Exchange (mặc định "(AMQP default)"); Routing key (chọn từ queue thì điền sẵn tên queue); Payload (`CodeEditor`). Không vào queue nào thì cảnh báo "Message published but not routed to any queue" |
| Peek messages   | Số message (1–50, mặc định 10). Mỗi message: payload (JSON thì format), routing key, exchange, properties, cờ redelivered                                                                          |
| Purge           | Gõ tên queue để xác nhận (spec chính, mục 4)                                                                                                                                                       |
| Delete          | Gõ `delete`. Liệt kê queue sẽ xóa                                                                                                                                                                  |

**Peek không lấy mất message:** backend gọi `get` với `ackmode: ack_requeue_true`, message trả lại queue. Ghi chú trong modal: message vừa xem được đánh dấu `redelivered`.

### 3.6 Tab Exchanges

```text
Exchanges (7)                                                         [↻]
 Name                    Type        Durable
 (AMQP default)          direct      Yes
 amq.direct              direct      Yes
 amq.topic               topic       Yes
```

- Chỉ xem. Exchange nội bộ (`internal`) ẩn đi. Exchange tên rỗng hiện là "(AMQP default)".

### 3.7 Tab Details

| Khối    | Nội dung                                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Connect | AMQP endpoint và trang quản lý mà Floci trả về (dùng từ container trong cùng docker compose), copy được. Ghi chú cho máy dev, mục 6 #3 |
| General | Engine, version, trạng thái, deployment mode, instance type, ngày tạo, ARN, broker ID (copy được)                                      |

## 4. Backend

### API

Như spec chính, mục 5. Tên queue/exchange nằm trong đường dẫn: trình duyệt `encodeURIComponent`, Express tự giải mã. Vhost luôn là `/`.

| API                                            | Việc                                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `GET /api/mq/:broker/queues`                   | Danh sách queue: tên, type, durable, messages                                            |
| `GET /api/mq/:broker/exchanges`                | Danh sách exchange (bỏ `internal`)                                                       |
| `PUT /api/mq/:broker/queues/:name`             | Tạo queue `{ durable }`. Đã có thì 409                                                   |
| `DELETE /api/mq/:broker/queues/:name`          | Xóa queue                                                                                |
| `POST /api/mq/:broker/exchanges/:name/publish` | `{ routingKey, payload }` → `{ routed }`. Exchange mặc định gửi tên rỗng (`amq.default`) |
| `POST /api/mq/:broker/queues/:name/peek`       | `{ count }` → danh sách message                                                          |
| `DELETE /api/mq/:broker/queues/:name/messages` | Purge                                                                                    |

- **User/pass:** trình duyệt gửi header `Authorization: Basic …` cho backend, backend chuyển nguyên sang RabbitMQ. Backend không lưu.
- **Tìm địa chỉ:** trình duyệt chỉ gửi broker ID. Backend gọi `DescribeBroker` để lấy `consoleURL` (vd: `http://172.26.0.5:15672`). Host là `localhost` (Floci chạy ngoài Docker) thì đổi thành host của `AWS_ENDPOINT_URL`, giống ElastiCache.
- **Lỗi:** broker không có (404 `BrokerNotFound`); broker chưa chạy (409 `BrokerNotReady`); RabbitMQ trả 401 → 401 `Unauthorized`; queue không có → 404 `QueueNotFound`; lỗi khác của RabbitMQ → 400 kèm `reason`; không kết nối được trong 5 giây → 502 `BrokerUnavailable`.
- Type của API khai báo ở `server/src/routes/rabbitmq/contract.ts`, web import qua alias `@server` (giống ElastiCache).

## 5. Kỹ thuật

### Package cần cài

User tự chạy (từ thư mục gốc repo):

```bash
npm install @aws-sdk/client-mq -w web --min-release-age=7
npm install @aws-sdk/client-mq -w server --min-release-age=7
```

Không cần thư viện AMQP: mọi thao tác queue đi qua API HTTP quản lý của RabbitMQ bằng `fetch` có sẵn.

### Cấu trúc thư mục

```bash
web/src/services/mq/
├── index.tsx, routes.ts, constants.ts, schemas.ts
├── credentials.ts             # user/pass theo broker trong sessionStorage
├── hooks/
│   ├── useMQ.ts               # MqClient qua /aws
│   ├── useBrokers.ts          # list, describe, create, delete, reboot
│   └── useRabbit.ts           # gọi backend: queue, exchange, publish, peek, purge
├── pages/                     # BrokerList, CreateBroker, BrokerDetail
└── components/                # SignIn, QueuesTab, ExchangesTab, DetailsTab, các modal

server/src/routes/rabbitmq/
├── contract.ts                # type và mã lỗi dùng chung với web
├── router.ts                  # route + zod
└── client.ts                  # tra consoleURL, gọi API quản lý của RabbitMQ
```

Dùng lại: `ActionBar`, `refreshAction`, `ConfirmModal`, `FormModal`, `FormFields`, `useZodForm`, `CodeEditor`, `CopyButton`, `Figure`, `EmptyState`, `emptyOrError`, `NotFound`, `useIsCompact`, `useNotify`, `formatDate`, `fetchJson`. Icon `web/public/icons/mq.svg` theo cùng khung với các icon cũ.

1. User cài package (mục 5). Icon, khai báo trong `registry.ts`.

## 9. Kết quả thử

**Đã thử trên Floci 2.4.0 (2026-11-09), console chạy trong compose:**

- **API (curl):** chưa đăng nhập / sai pass (401); tạo queue, tạo trùng (409); publish vào được queue và không vào queue nào (`routed: false`); danh sách queue, exchange; peek (message vẫn còn); count > 50 (400); purge; xóa queue; xóa queue không có (404); broker không có (404).
- **Giao diện:** chụp ở 1288 và 390px: danh sách broker, form đăng nhập, tab Queues, modal Peek, tab Exchanges, tab Details. Không màn nào cuộn ngang.
- **Bấm thật trong giao diện** (Chrome headless qua DevTools Protocol, 17 bước, đều qua): tạo broker (password ngắn bị chặn), đăng nhập sai rồi đúng, tạo queue và tạo trùng, publish vào queue và không vào queue nào, số message tăng, peek, Auto refresh, purge, xóa queue, tab Exchanges, Sign out, Reboot, xóa broker.

**Lỗi tìm thấy khi thử và đã sửa:**

- Tạo queue báo `InternalError` dù đã tạo: RabbitMQ trả 201 với body rỗng.
- Peek: không có property nào thì RabbitMQ trả `[]` thay vì object.
- Lỗi 404 hiện đường dẫn đã mã hóa (`/queues/%2F/…`): đổi thành câu dễ đọc.
- Dòng mô tả của broker luôn ghi `RUNNING`: chỉ hiện khi khác `RUNNING`.
- Đăng nhập sai rồi đúng vẫn bị báo sai: lỗi 401 nằm trong cache của TanStack Query → query key có cả user/pass.
- Queue vừa tạo làm trang crash: RabbitMQ chưa có thống kê nên không trả `messages` → server trả `null`, web hiện "—".
- Icon phong bì (giống email): đổi thành message xếp hàng trong ống, có mũi tên ra.

**Quyết định lúc làm:** nút **Sign out** nằm ở header trang; `ValueEditor` chuyển sang `shared` để Publish dùng lại; `FormInput` thêm prop `type` (ô password); hàm đổi `localhost` thành host của Floci tách ra `server/src/flociHost.ts`, ElastiCache dùng chung.
